Deployment & Workflows

Two Sovereign Operational Modes

Choose the deployment model that best fits your workflow. Click either mode below to explore its architectural details and interface workflows.

Workstation Sovereign Security

Air-Gapped, Zero-Cloud Desktop Operation

Mode 1 operates entirely locally on your physical machine with zero network listening sockets or external communication. Designed for developers and security analysts who require immediate access to credentials directly from their desktop or development shell.

  • Modern 3-Pane Desktop GUI (PySide6): Dark & Light themes, live search filter, categories, and tags.
  • RFC 6238 TOTP Arc: Embedded circular SVG/Qt countdown timer with 1-click token copying.
  • Rich / Typer CLI: Terminal tables, clipboard auto-erase in 30 seconds, and scriptable headless JSON output.
  • Inactivity Auto-Lock: Memory is zeroed via SecureBuffer after 60 seconds of idle time.
# Launch Modern Desktop UI
python SimpleCredentialManagerUi.py

# Launch Interactive CLI
python SimpleCredentialManagerCli.py interactive

Encrypted via Argon2id (64MB) + Two-Tier Envelope (KEK/DEK)

Self-Hosted • WebCrypto AES-GCM

SCM Server Mode & Zero-Dependency Web Dashboard

Mode 2 hosts Simple Credential Manager as a lightweight, hardened web daemon. Ideal for home servers, self-hosted Raspberry Pis, or reverse-proxy subpaths (e.g. /password/) behind Nginx with hardware device whitelisting.

  • Physical Out-of-Band Whitelisting: Devices register via a secret token (/enroll?secret=...) and can strictly only be approved locally on the server host machine via the CLI (scm server devices approve <fingerprint>).
  • Subtle 404 Defense: Unauthorized requests receive nondescript HTTP 404 {"detail": "Service unavailable"}, thwarting port scanners and honeypot crawlers.
  • Device-Bound WebCrypto Transport Encryption: Request payloads (passwords, master unlock, secret CRUD) are encrypted client-side using AES-256-GCM keyed via HKDF from the approved device token.
  • Docker Containerized: Unprivileged UID 10001, persistent volume mounts for vault data/config, and internal CLI alias.
# Start Server Mode via CLI
scm server start --host 0.0.0.0 --port 8080

# Or run with Docker Compose
docker compose -f container/docker-compose.yml up -d --build

# Approve Device on Server Host CLI
scm server devices approve <fingerprint_or_id>

High-Assurance Architecture

Built Without Compromise. Engineered for Paranoia.

Cloud password managers are high-value honeypots susceptible to server-side breaches and supply chain attacks. SCM replaces the cloud with local, cryptographically airtight sovereignty.

Military-Grade Cryptography

Derives master keys using Argon2id (the memory-hard password hashing competition winner), rendering GPU/ASIC attacks ineffective.

  • Two-Tier Envelope Encryption (KEK + DEK)
  • AES-256-GCM authenticated cipher with tag verification
  • Instant master password rotation with zero re-encryption of data

SecureBuffer Memory Zeroing

Python immutable strings leave sensitive artifacts in process memory. SCM overrides memory boundaries using bytearray wiping routines.

  • Explicit C-style memset overwrites RAM with zeros upon lock
  • Automated 60-second inactivity lock clears DEK from memory
  • Prevents core dump, swap file, and cold boot extraction

Zero-Trace OS Clipboard

Copying credentials without leaking to third-party clipboard monitors, cloud syncs, or system history buffers.

  • Sets Windows ClipboardViewerIgnore / ExcludeClipboardContentFromMonitorProcessing
  • macOS org.nspasteboard.ConcealedType isolation
  • Hard 30-second background eraser wiping clipboard automatically

SQLite WAL & Blind Indexing

High performance transactional storage with row-level encryption and zero-knowledge name querying.

  • Write-Ahead Logging (WAL) ensures atomic crash resilience
  • HMAC-SHA256 Blind Indexing enables instant O(1) searches
  • Row-level AEAD: only decrypted when individually queried

RFC 6238 TOTP 2FA Engine

Ditch standalone authenticator apps. SCM generates real-time TOTP tokens directly in your CLI or desktop window.

  • Compatible with Google Authenticator, Authy, and Duo
  • QR code camera scanning and otpauth:// URI ingestion
  • Encrypted TOTP secret storage with row-level AEAD protection

Tamper-Proof Audit Trail

Every authentication event, secret access, export, and failed password attempt is logged into a structured, verifiable trail.

  • Redacts sensitive attributes automatically before writing to disk
  • Exponential lockout timer defends against brute-force attacks
  • Standalone, non-cloud JSONL audit trail with monotonic ordering
Quickstart Guide

Get Up and Running in Seconds

Install SCM as a single standalone binary or through Python pip. No cloud accounts, no subscription keys, no network connection required.

1. Clone the repository and install requirements in your virtual environment:

git clone https://github.com/abhishekraha/SimpleCredentialManager.git
cd SimpleCredentialManager
pip install -r requirements.txt

2. Launch the Modern UI or CLI:

# Launch Desktop UI (Modern PySide6 interface by default)
python SimpleCredentialManagerUi.py

# Or launch Modern CLI
python SimpleCredentialManagerCli.py

1. Install dependencies via Homebrew and pip:

brew install python@3.12
git clone https://github.com/abhishekraha/SimpleCredentialManager.git
cd SimpleCredentialManager && python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

2. Run Modern UI or CLI:

python3 SimpleCredentialManagerUi.py # Modern PySide6 UI
python3 SimpleCredentialManagerCli.py # Interactive CLI

1. Setup in standard Linux terminal (Wayland and X11 supported):

sudo apt install python3-tk xclip # On Ubuntu/Debian
git clone https://github.com/abhishekraha/SimpleCredentialManager.git
cd SimpleCredentialManager && pip install -r requirements.txt

2. Run Modern UI or CLI:

python3 SimpleCredentialManagerUi.py # Modern PySide6 UI
python3 SimpleCredentialManagerCli.py # Interactive CLI
System Architecture

Two-Tier Envelope Cryptography

How SCM protects your credentials through cryptographic isolation between Master Passwords and Data Encryption Keys.

Cryptographic Lifecycle

Traditional vaults derive an encryption key straight from your master password and encrypt the entire file. SCM decouples key verification from data decryption using an Envelope Model:

1

Master Password → Argon2id KDF

Computes a 256-bit Key Encryption Key (KEK) using 64MB memory cost factor, completely neutralizing brute-force hardware.

2

Encrypted DEK Unwrap

The KEK decrypts the randomized Data Encryption Key (DEK). If the master password is modified, only the DEK envelope is re-encrypted in 1ms.

3

Row-Level SQLite AEAD

Each secret payload is independently encrypted with a unique 96-bit AES-GCM IV and verified with HMAC blind indexing.
